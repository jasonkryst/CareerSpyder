# Multi-User Authentication — Implementation Plan (GH #31, v1.0.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close GH #31 and ship v1.0.0 by adding full multi-user authentication with per-user data isolation: dedicated users table, invite-link registration, session-cookie auth, sources migrated from JSON to DB (per user), and all data tables scoped by `user_id`.

**Architecture decisions:**
- **Sessions:** Starlette `SessionMiddleware` (itsdangerous signed cookie). `SECRET_KEY` env var required at startup (startup fails with a clear error if absent in production; warns in dev).
- **Passwords:** `passlib[bcrypt]`. Initial admin seeded from `ADMIN_USERNAME` + `ADMIN_PASSWORD_HASH` env vars at startup. Invite registrants set their own password on registration.
- **Sources storage:** New `sources` DB table. Shared base columns (`id`, `user_id`, `type`, `name`, `secondary`) + `config JSONB` for all type-specific fields. Existing `sources.json` import tool (`/settings/data/import-sources`) for admins migrating live installs.
- **Settings table:** Redesigned — `CHECK (id = 1)` singleton replaced by `user_id UUID PK`.
- **Scheduler:** One cron job iterates all users with sources; calls `run_once` per user sequentially.
- **geocoded_locations:** Stays global (shared geo cache). No `user_id`.
- **Backfill:** Admin user created at startup; all pre-existing rows with NULL `user_id` backfilled to admin's ID in `seed_admin_if_empty`.
- **New dependencies:** `passlib[bcrypt]>=1.7.4`, `itsdangerous>=2.1`.

**Tech stack:** FastAPI, Starlette `SessionMiddleware`, `passlib[bcrypt]`, psycopg3 pool, Alembic (raw SQL migrations), Jinja2.

**Spec:** GH #31 "Authentication: Add user login and authentication" in milestone v1.0.0.

## New Schema (Migration 0002)

### `users`
```sql
CREATE TABLE users (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username    TEXT NOT NULL UNIQUE,
    email       TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    role        TEXT NOT NULL DEFAULT 'member',  -- 'admin' | 'member'
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### `invite_tokens`
```sql
CREATE TABLE invite_tokens (
    token       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email       TEXT NOT NULL,
    created_by  UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at  TIMESTAMPTZ NOT NULL,
    used_at     TIMESTAMPTZ
);
```

### `sources`
```sql
CREATE TABLE sources (
    id          TEXT PRIMARY KEY,
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    type        TEXT NOT NULL,
    name        TEXT NOT NULL,
    secondary   BOOLEAN NOT NULL DEFAULT FALSE,
    config      JSONB NOT NULL DEFAULT '{}',
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX sources_user_id ON sources(user_id);
```

### Alter existing tables
```sql
-- Add nullable user_id (backfilled at startup from admin seed):
ALTER TABLE jobs           ADD COLUMN user_id UUID REFERENCES users(id);
ALTER TABLE runs           ADD COLUMN user_id UUID REFERENCES users(id);
ALTER TABLE job_status_history ADD COLUMN user_id UUID REFERENCES users(id);

-- Redesign settings: drop singleton CHECK, add user_id as new PK
ALTER TABLE settings DROP CONSTRAINT settings_pkey;
ALTER TABLE settings ADD COLUMN user_id UUID REFERENCES users(id);
ALTER TABLE settings ADD PRIMARY KEY (user_id);
-- old id column can be dropped after backfill

-- Indexes for per-user scans:
CREATE INDEX jobs_user_id ON jobs(user_id);
CREATE INDEX runs_user_id ON runs(user_id);
CREATE INDEX job_status_history_user_id ON job_status_history(user_id);
```

### `app/web/auth.py`
```python
from fastapi import Depends, HTTPException, Request
from fastapi.responses import RedirectResponse

def get_current_user(request: Request) -> dict | None:
    """Returns the session user dict, or None if not logged in."""
    user_id = request.session.get("user_id")
    if not user_id:
        return None
    with request.app.state.pool.connection() as conn:
        return db.get_user_by_id(conn, user_id)

def require_user(request: Request, user: dict | None = Depends(get_current_user)) -> dict:
    """FastAPI dependency: raises 401 if not authenticated."""
    if user is None:
        raise HTTPException(status_code=401)
    return user
```

### `app/web/main.py` additions
```python
from starlette.middleware.sessions import SessionMiddleware

# Startup fails if SECRET_KEY is missing in production:
secret_key = os.environ.get("SECRET_KEY", "")
if not secret_key:
    # Allow insecure dev default; warn loudly
    secret_key = "dev-insecure-secret-change-me"
    logger.warning("SECRET_KEY not set — using insecure dev default. Set SECRET_KEY in production.")

app.add_middleware(SessionMiddleware, secret_key=secret_key, max_age=7 * 24 * 3600)

# 401 → redirect to login (all routes are HTML pages):
@app.exception_handler(401)
async def auth_redirect(request, exc):
    return RedirectResponse(url=f"/login?next={request.url.path}")
```

## Self-Review Notes

- **Dependency order for SessionMiddleware:** must be added before `OriginCheckMiddleware` in registration (so it's innermost, running after security checks). In code: `app.add_middleware(SessionMiddleware, ...)` then `app.add_middleware(OriginCheckMiddleware)` then `app.add_middleware(SecurityHeadersMiddleware)`.
- **`geocoded_locations` stays global:** no `user_id` needed; pure geo cache shared across all users.
- **`_sources_lock` in config.py becomes obsolete** once CRUD moves to the DB; remove it.
- **Scheduler passes `user_id` to `run_once`** indirectly: `run_once` receives `list[SourceConfig]` as before; the caller (`run_and_notify`) now loops per user and queries the DB for each user's sources.
- **Backfill in `seed_admin_if_empty`:** one SQL: `UPDATE jobs SET user_id = %s WHERE user_id IS NULL` (same for runs, job_status_history, settings — after creating the admin and inserting their settings row).
- **`settings` table:** after migration, the `id` column is dropped and `user_id UUID PK` replaces it. The old `seed_settings_if_empty(conn, smtp_host, ...)` becomes `seed_settings_if_empty(conn, user_id, smtp_host, ...)` called during `seed_admin_if_empty`.
