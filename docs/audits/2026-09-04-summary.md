## Cross-cutting findings

A few issues were found independently by more than one audit, from
different angles — that agreement is worth weighing above any single
report's severity label.

**SQLite concurrency (locking / no WAL mode).** The Performance audit
(H1), Database audit (C2), and Core-functionality audit (H1 — the
`/check-urls` background task bypassing `orchestrator._run_lock`) all
independently identified the same underlying gap: one shared
`sqlite3.Connection` is used across the web server's threads, the
APScheduler thread, and now a background task that doesn't take the
run lock, with no WAL mode or explicit `busy_timeout` set. Currently
masked by sqlite3's implicit 5s default timeout, this is a real,
reachable "database is locked" failure mode under ordinary single-user
use (e.g. browsing while a scheduled run is in progress), not a
hypothetical. **Recommend fixing this as one unit of work**: enable WAL
mode + an explicit `busy_timeout`, and make `/check-urls` take the same
lock `run_once()` does.

**Indeed adapter's unstable dedup key.** Both the Core-functionality
audit (M3) and the Database audit (C7) independently flagged that
`app/adapters/indeed.py` dedups on a URL that still carries tracking
query-string params, unlike `linkedin.py`, which explicitly strips them.
Concrete, reproducible effect: the same Indeed posting can silently be
re-reported (and re-emailed) as "new" on a later run purely because a
tracking param changed.

**Blocking network calls bypassing async.** The Performance audit (H2)
and the Security audit's N1 both center on the same code path —
`app/web/routes_jobs.py`'s zip/location-radius filter calling Nominatim
synchronously and uncached inside an `async def` route. Performance
frames it as an event-loop stall (up to ~10s freezing every other
request); Security frames the same lack of caching/throttling as an
unauthenticated DoS/ToS-risk vector reachable via a plain `<img>` tag.
Same fix serves both: wrap in `run_in_threadpool` (or make it truly
async) and cache/rate-limit like the existing job-location geocoding
path already does.

**Encoding correctness in scraped/hand-edited data.** The i18n audit's
two Medium findings (Latin-1 fallback decoding in `generic_html.py`,
missing `encoding="utf-8"` on `sources.json` reads/writes in
`config.py`) are narrow one-line fixes but sit in exactly the code path
the Database and Core-functionality audits already flagged as fragile
(adapter dedup/parsing robustness) — worth batching into the same pass.

## Suggested priority order

1. **SQLite concurrency fix** (WAL + busy_timeout + lock the `/check-urls` path) — three audits, real production failure mode, small fix.
2. **Security H1/M1** (SSRF via source URLs + no CSRF) — still open since the 2026-08-19 audit, unchanged; the documented no-auth trust model doesn't cover a drive-by attack from an external webpage.
3. **Indeed dedup key normalization** — one-line fix, matches the existing LinkedIn pattern, stops spurious re-notifications.
4. **Geocoding filter: async + cache/throttle** — fixes a real event-loop stall and closes N1's DoS vector in one change.
5. **a11y H1** (confirm-modal has no accessible name) — affects every destructive action in the app for screen-reader users.
6. **Testing H1/H2** (`browser.py` render path and Infor's pagination logic are effectively untested) — the two riskiest, least-covered pieces of scraping logic in the app.
7. Everything else, roughly in the Medium lists of each report — none blocking, all concrete and independently fixable.

## Note on scope

The Accessibility audit was static-only: both `chrome-devtools-mcp` and
the `playwright` MCP server failed to connect in this environment, and
no live browser session was available, so contrast ratios were computed
manually from the CSS custom properties rather than measured, and no
screen-reader/keyboard pass was actually driven. Treat its findings as
high-confidence on markup/ARIA (verifiable from source) and
lower-confidence on anything that would normally need a live render.

These reports are uncommitted (`docs/audits/2026-09-04-*.md`, this
summary included) — nothing has been added to git yet, pending review.
